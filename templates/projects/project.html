Swarnil Design System

Six sites that looked like six people made them, rebuilt on one token-first system in thirty days — and 40% less CSS at the end of it.

The brief, written to myself

Six sites, three themes, a YouTube channel and a link page. Every one of them had its own idea of what a button was, and I had written all of them. The audit took an afternoon and produced one number that made the argument on its own: nineteen button styles.

The temptation was to pick the nicest one and copy it around. I have done that before. It survives exactly until the next site, because copying a button does not decide anything — it just moves the decision to the next person, who is me, in three months, with less context.

The constraint I set first

No framework, no runtime, no build step required to use it. If a designer cannot drop one stylesheet into a CodePen and get the whole system, it is not a system, it is a toolchain.

What I did instead

Tokens first, and nothing visual for the first four days. Eight OKLCH ramps, then a second tier that names what a step is for — --fg-muted, not --ink-500. A component may only read the second tier. That single rule is the entire customisation API: override a token after the import and the whole system moves.

A palette is a set of nice colours. A system is a set of promises about which colour is allowed where.

Nine cascade layers

The specificity fights stopped the day the layers went in. Every rule lives in a layer; an unlayered rule beats every layer and is therefore a bug, which is a sentence a linter can enforce.

What it cost

Thirty days, most of them spent deleting. The hardest single decision was dropping the second typeface: the display face was doing nothing that weight and tracking could not do, and every extra font is a request, a flash and a decision for whoever comes next.

Where it ended up

Every site I own now imports one stylesheet. The Ghost themes, the link page, the course site and the docs all read the same tokens, and a change to --accent moves all of them. The CSS I ship went from 62 KB to 37 KB gzipped, and most of that saving is code I deleted rather than code I optimised.

The part I did not expect: the system made the writing easier. When you have stopped deciding what a card is, you spend the whole session on what the card should say.

Build log

Thirty days, in order

Written at the end of each week, not reconstructed afterwards. The wrong turns are still in it.

  1. Day 1 · Jun 02

    Kick-off — six sites, one audit

    I opened all six sites side by side and counted button styles. Nineteen. That was the whole business case.

  2. Day 4 · Jun 05

    The token layer lands

    Eight OKLCH ramps and a second tier that says what a step is for. Nothing visual shipped this week and it was the most important one.

  3. Day 9 · Jun 10

    Nine cascade layers

    The specificity fights stopped the day the layers went in. One rule: a file may only reference something from a lower layer.

  4. Day 16 · Jun 17

    Components, one file each

    Forty-one modules. Each one has to argue for itself in the file header, which killed about six of them before they were written.

  5. Day 24 · Jun 25

    The broadcast layer

    Thumbnails, scenes and lower thirds, sized in cqi so one canvas renders at 1280 and in a docs column.

  6. Day 30 · target

    Ship v1 and the docs site

    Fifty-eight pages, built from markdown, every class demoed by the markup it documents.
